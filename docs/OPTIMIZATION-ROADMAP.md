## DataAI 功能分析与优化方向

本文档用于整理当前 DataAI 的核心能力，以及后续可以演进和优化的方向，方便后续规划版本和开发节奏。

---

## 一、当前核心能力概览

- **多数据库支持**
  - MySQL / MariaDB / PostgreSQL / SQLite / Oracle / SQL Server / Redis
  - 统一的连接管理、驱动检测、超时控制

- **连接与配置管理**
  - 添加/编辑/删除数据库连接，连接测试
  - 从 Navicat 导入连接（注册表 + `.ncx` 文件）
  - SQLite 配置库（连接、AI 模型、提示词、记忆、Token 统计）

- **查询与结果**
  - SQL 编辑器（自动完成、快捷键、F5 执行）
  - 查询结果表格、导出（CSV/Excel/JSON）
  - 结果表中直接编辑、自动生成 `UPDATE` / 删除行等

- **AI 能力（LangGraph Agent）**
  - 自然语言 → SQL（自动选表 + 拉结构 + 生成 SQL）
  - AI 自动修复执行失败的 SQL
  - AI 建表（多轮对话、参考现有表风格）
  - AI 改表（基于当前表结构生成 ALTER 语句）
  - Redis 命令生成

- **长期记忆系统**
  - 命名规范记忆（表/字段命名风格）
  - 查询模式记忆（user_intent ↔ generated_sql）
  - 纠错记录（AI 错误 SQL 与人工修正 SQL）
  - 表级摘要 + 定期压缩（避免记忆膨胀）

- **工程化与分发**
  - PyInstaller 打包为 `DataAI.exe`
  - 版本号脚本与 `VERSION.txt`
  - 一键发布脚本：发布到 GitHub + Gitee Releases
  - VSCode 启动配置：运行、打包、发布、Dry-Run
  - 新增 CLI：命令行查看连接/库/表、AI 查询、AI 建表/改表

## 二、体验层优化（短期可以落地，**建议优先级：P1**）

### 1. 查询历史与收藏（P1）

- **目标**
  - 让用户可以方便地回看和复用历史 SQL，尤其是 AI 生成的查询。

- **思路**
  - 在 UI 中增加「查询历史」面板或 Tab：
    - 显示最近 N 条查询（SQL + 执行时间 + 连接/库）。
    - 支持「收藏」、「重命名」、「按连接/库过滤」。
  - 将 AI 生成的 SQL 自动纳入历史（标记来源为 AI）。
  - CLI 侧增加 `db-ai history` 命令查看最近若干条查询。

### 2. AI 交互过程可视化（P1）

- **目标**
  - 让用户清楚知道 AI 在做什么：选表、拉结构、查枚举、生成 SQL 等。

- **思路**
  - 利用 LangGraph 的状态（`current_step`、`agent_iterations`、`selected_tables`）：
    - 在查询区域增加一个「AI 步骤」小面板，展示本次：
      - 召回记忆是否成功；
      - 使用了哪些工具（search tables / get schema / get enum）；
      - 实际涉及哪些表。
  - 优化状态栏提示文案（已经开始做）：从「召回记忆」自然过度到「正在请求 AI / 正在综合结果」。

### 3. 错误提示友好化（P1）

- **目标**
  - 避免用户直接看到驱动/SQLAlchemy 的 raw 报错，改为面向业务的中文提示。

- **思路**
  - 对常见错误进行模式匹配与翻译：
    - 连接失败（网络不可达/超时/认证失败）；
    - 驱动缺失（缺少 `oracledb`、`pyodbc`、`psycopg2` 等）；
    - SQL 语法错误 / 表不存在 / 列不存在。
  - 在自动修复 SQL 时，明确提示：
    - 「已触发 AI 自动修复（第 X 次）」；
    - 「AI 修复失败，请手动检查 SQL」。

## 三、AI 能力深挖（基于现有 Memory 系统，**建议优先级：P2**）

### 1. 记忆系统可视化与管理（P2）

- **目标**
  - 把现在已经很强的 MemoryStore「可视化」，增强可解释性和可控性。

- **思路**
  - 在设置或独立 Tab 中增加「AI 记忆」页面：
    - 显示：
      - 命名规范样例（naming_conventions）；
      - 相似历史查询（query_patterns）；
      - 表级摘要（table_summaries）；
      - 最近纠错记录（corrections）。
    - 提供操作：
      - 清空当前连接/库记忆；
      - 导出/导入记忆（方便备份或迁移）。

### 2. 面向业务的查询模板（P3）

- **目标**
  - 对于 BI/运营场景，提供「半结构化模板」比纯自然语言更稳定。

- **思路**
  - 在某个连接下，允许配置「业务查询模板」：
    - 如「用户留存分析」「订单转化漏斗」「最近30天营收趋势」等。
  - 模板内部调用 LangGraph，但 prompt 中包含更强约束和示例，提升稳定性。

## 四、CLI 与自动化增强（**建议优先级：P2**）

### 1. CLI 使用体验（P2）

- **现状**
  - 已支持：
    - `connections / databases / tables`
    - `ai-query`
    - `ai-create-table`
    - `ai-edit-table`

- **可优化点**
  - 增加默认连接配置：
    - `db-ai config set-default-conn <id>`；
    - 后续命令可省略 `--conn`。
  - 增加历史查询查看：
    - `db-ai history [--limit 20]`，从 config_db 中读取最近 AI 查询或手工查询。
  - 增加 `--dry-run` 开关：
    - 对非 SELECT 语句，`--dry-run` 仅生成并打印 SQL，不执行。

### 2. CI/CD 集成示例（P3）

- **目标**
  - 提供 GitHub Actions / Gitee CI 的示例工作流，方便自动化测试打包流程。

- **思路**
  - 在 `docs` 或 `.github/workflows/` 中提供模板：
    - 每次打 tag：
      - 运行测试；
      - 调用 `build_exe.bat`；
      - 调用 `publish_release.py --dry-run` 作为验证。
    - 用户可自行解注释实际发布步骤。

## 五、性能与稳定性（**建议优先级：P2**）

### 1. 大库/大表性能优化（P2）

- **表/结构加载**
  - 支持：
    - 分页/分批加载表列表；
    - 为表结构缓存增加 TTL 和最大条数配置（在设置中暴露）。

- **大结果集展示**
  - 对超过一定行数的查询：
    - 自动添加 LIMIT 提示；
    - 在结果表中启用虚拟滚动或分段加载。

### 2. 日志与诊断模式（P2）

- **目标**
  - 方便用户复现问题和反馈 bug。

- **思路**
  - 增加「诊断模式」开关：
    - 将关键日志（AI 请求/响应摘要、SQL 执行耗时、错误栈）集中输出到一个独立日志文件；
    - 在 UI 中提供「导出诊断日志」按钮。

## 六、新功能方向（中长期，**建议优先级：P3**）

### 1. 轻量级数据可视化（P3）

- **目标**
  - 在不引入复杂 BI 的前提下，为常规报表场景提供基础图表能力。

- **思路**
  - 在结果区域增加「图表视图」：
    - 支持折线图、柱状图、饼图；
    - 用户选择 X/Y 轴列；
    - 配合 AI：「画一下最近 30 天订单趋势」→ 自动生成 SQL + 切图表。

### 2. 配置与多机同步（P3）

- **目标**
  - 让同一用户在多台机器上共享连接配置、AI 模型配置、提示词等。

- **思路**
  - 支持导出/导入整套配置（包含连接、模型、prompt、记忆摘要）。
  - 未来可接入简易「远程配置中心」（例如基于 Gitee/GitHub 私有仓库的同步脚本）。

---

## 七、优先级建议（供后续排期参考）

1. **高优先级（立即提升体验）**
   - 查询历史与收藏；
   - AI 记忆可视化面板；
   - 错误提示友好化。

2. **中优先级（增强“专业感”与可解释性）**
   - CLI 进一步完善（默认连接、dry-run）；
   - 诊断模式与集中日志；
   - 大库/大表性能优化。

3. **中长期（产品力升级）**
   - 轻量级数据可视化；
   - 业务查询模板；
   - 多机配置/记忆同步。
