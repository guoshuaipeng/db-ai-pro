# 版本管理说明

本文档合并「版本号统一管理」与「版本号自动生成」两部分内容。

---

## 一、版本号统一管理

### 📋 版本号定义位置

项目采用**单一版本号源**的管理方式。

**主版本号源（唯一修改位置）**：`src/__init__.py`

```python
__version__ = "0.2.0"
```

⚠️ **重要**：这是项目中**唯一应该修改版本号的地方**。所有其他地方的版本号都从这里导入。

### 📍 版本号的使用位置

**已自动导入（无需手动更新）**：

- `src/config/settings.py` — 从 `src.__version__` 导入
- `src/core/update_checker.py` — 版本比较和更新检查
- `src/gui/dialogs/update_dialog.py` — 显示当前版本号
- `src/gui/dialogs/about_dialog.py` — 显示版本号

**需要手动同步**：

- **`pyproject.toml`**：TOML 无法从 Python 导入，需与 `src/__init__.py` 保持同步。

### 🔧 如何更新版本号

1. 修改 `src/__init__.py` 中的 `__version__`
2. 同步修改 `pyproject.toml` 中的 `version`
3. 运行应用，检查关于对话框、更新检查器等处的版本号显示

### 📝 版本号命名规范

建议使用 [语义化版本](https://semver.org/lang/zh-CN/)：`主版本号.次版本号.修订号`。

## 二、版本号自动生成

### 📋 概述

项目已实现**自动生成日期时间版本号**。打包时会根据当前日期时间生成版本号，格式为 `YYYY.MM.DD.HHMM`。

### 🎯 版本号格式

- **格式**：`YYYY.MM.DD.HHMM`（年.月.日.时分）
- **示例**：`2025.01.20.1430` 表示 2025 年 1 月 20 日 14:30 构建

### 🔧 工作原理

**开发环境**：每次运行应用时，版本号为当前日期时间（实时生成）。

**打包环境**：打包脚本运行 `scripts/generate_build_version.py` 生成版本号，更新 `pyproject.toml`，并设置 `BUILD_VERSION` 环境变量，打包出的 EXE 版本号固定为该次构建时间。

**生成脚本**：`scripts/generate_build_version.py`

### 📝 使用方法

- **手动生成**：`python scripts/generate_build_version.py`
- **打包时**：执行 `build_exe.bat` / `build_exe.sh` 时会自动生成版本号（流程内含「生成构建版本号」步骤）。

### 🔍 版本号使用位置

打包脚本会自动更新：

1. `src/__init__.py` — 通过环境变量 `BUILD_VERSION` 设置
2. `pyproject.toml` — `version = "YYYY.MM.DD.HHMM"`
3. `build_mac.spec`（如存在）— `CFBundleShortVersionString` / `CFBundleVersion`

GitHub Release 标签、README 等如需与版本一致，请手动同步。

### 💡 使用场景

- **开发环境**：版本号为当前时间，便于区分不同运行。
- **打包环境**：版本号包含构建时间，可追溯；每次打包自动生成，无需手改。

### 🎯 与更新检查的兼容性

更新检查器从 `src.__version__` 读取当前版本号，版本比较使用字符串比较，与日期时间格式兼容。GitHub Release 的版本号可使用日期时间格式或语义化版本。

---

**记住**：日常只需改 `src/__init__.py` 与 `pyproject.toml`；打包时版本号会自动生成。
