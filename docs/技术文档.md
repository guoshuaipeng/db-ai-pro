## 4. 核心模块说明

### 4.1 入口与启动（src/main.py）

- 设置 `sys.path`、配置 `logging`。
- 创建 `QApplication`，加载图标、应用名。
- 初始化配置库、国际化（TranslationManager）、全局异常处理（ExceptionHandler）。
- 创建并显示 `MainWindow`，运行事件循环。

### 4.2 配置（config）

- **settings.py**：应用级设置（如语言、主题相关），可与注册表或本地文件联动。
- **core/config_db.py**：内置配置库（如 SQLite），用于存储连接信息、AI 模型配置等。

### 4.3 数据库核心（core）

- **database_connection.py**：连接参数模型（类型、主机、端口、库名、用户、密码等）。
- **database_manager.py**：基于 SQLAlchemy 的连接管理、执行 SQL、获取表/列元数据、适配多数据库方言。
- **schema_cache.py / tree_cache.py**：表结构与树形数据缓存，减少重复查询。

### 4.4 AI 核心（core）

- **ai_client.py**：封装 OpenAI 兼容客户端；调用提示词模块生成 SQL（查询、建表、改表）；可记录 Token 使用。
- **ai_model_config.py / ai_model_storage.py**：模型配置的模型与持久化（API Key、Base URL、默认模型等）。
- **prompt_config.py**：提示词配置的加载与切换。
- **prompts/**：按场景拆分的提示词（query_prompts、create_table_prompts、edit_table_prompts 等），包含数据库类型、表结构等上下文。

### 4.5 GUI 分层

- **main_window.py**：主窗口布局（菜单、工具栏、连接树、SQL 编辑器、结果区、状态栏）。
- **handlers**：响应用户操作，调用 core 与 workers，更新 UI（如 query_handler 执行 SQL、tree_data_handler 刷新树）。
- **workers**：耗时操作在 QThread 或 QThreadPool 中执行，通过信号将结果回传 UI 线程，避免界面卡顿。
- **dialogs**：连接、导入、设置、AI 模型、表结构同步、更新等弹窗。
- **widgets**：可复用的 SQL 编辑器、结果表、连接树、建表/改表 Tab、Redis 视图等。

### 4.6 工具（utils）

- **navicat_importer.py**：从注册表或 .ncx 解析 Navicat 连接，解密后转为本应用连接配置。
- **registry_helper.py**：Windows 下读注册表（如 Navicat 存储路径、语言设置持久化）。
- **exception_handler.py**：全局异常捕获与友好提示。
- **toast / toast_manager**：轻量消息提示。

## 5. 关键流程简述

### 5.1 连接与树展示

1. 用户添加/编辑连接 → `connection_dialog` 收集参数 → 写入配置库。
2. 选择连接时，`connection_init_worker` 在后台建立连接并拉取库/表列表。
3. `tree_data_handler` 与 `connection_tree` 根据数据刷新树节点；可选 `tree_cache` 做缓存。

### 5.2 SQL 执行与结果展示

1. 用户在 `sql_editor` 输入 SQL 或由 AI 填入。
2. `query_handler` 调用 `execute_sql_worker` 在后台执行。
3. 结果通过信号传回，由 `multi_result_table` 展示；支持多标签页、排序、筛选、单元格编辑生成 UPDATE、导出 CSV/Excel/JSON。

### 5.3 自然语言转 SQL（AI）

1. 用户输入自然语言，当前连接与可选“当前 SQL/表”作为上下文。
2. `ai_worker` 调用 `ai_client`，结合 `query_prompts` 与当前库表结构（及数据库类型）生成 SQL。
3. 生成的 SQL 可自动填入编辑器并执行，或仅填入由用户确认后执行。

### 5.4 AI 建表 / 改表

1. **建表**：`create_table_ai_worker` + `create_table_prompts`，多轮对话收集需求，可选参考表；`ai_client` 生成 CREATE TABLE，由 `database_manager` 执行。
2. **改表**：`edit_table_ai_worker` + `edit_table_prompts`，基于当前表结构 + 自然语言生成 ALTER TABLE，预览后执行。

### 5.5 表结构同步

1. `schema_sync_dialog` 选择源/目标连接与库。
2. 使用 `database_manager` 或专用 worker 获取两边表结构并 diff。
3. 生成 DDL 脚本，用户预览后批量执行。

## 6. 数据与配置存储

- **连接与 AI 模型配置**：由 `config_db` 管理，通常为本地 SQLite 或等价存储；密码等敏感字段需加密或受控访问。
- **语言、窗口状态等**：通过 `settings` + 注册表（Windows）或配置文件持久化。
- **提示词模板**：可由 `prompt_config` 从文件或配置库加载，便于按环境/用户定制。

---

## 7. 依赖与运行

- 安装：`pip install -e .` 或根据 `pyproject.toml` 安装依赖；可选安装数据库驱动（pymysql、psycopg2-binary、cx-Oracle、pyodbc 等）。
- 运行：`python src/main.py` 或命令行 `dataai`（安装后）。
- 测试：`pytest`（测试目录 `tests/`）；代码风格：black、flake8。

---

## 8. 扩展与维护建议

- **新增数据库类型**：在 `database_manager` 中扩展方言与驱动；连接模型与 UI 增加对应选项。
- **新增 AI 能力**：在 `core/prompts` 增加新场景提示词，在 `ai_client` 中增加对应调用；需要时在 `gui/workers` 增加专用 worker。
- **新 UI 能力**：优先在 `handlers` 中写逻辑，耗时操作放入 `workers`，保持界面响应。
- **版本与更新**：`update_checker` 与 `update_dialog` 配合，检查新版本并提示下载或更新说明。
