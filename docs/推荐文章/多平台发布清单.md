## 用 Chrome DevTools MCP 协作发文

在 Cursor 中启用 **Chrome DevTools** MCP（本仓库配置里一般为 `user-chrome-devtools`），AI 可操控**已连接到该 MCP 的本机 Chrome** 中的页面（与 Cursor **内置浏览器**不是同一会话）。

**重要：默认并不是你桌面的那颗「日常 Chrome」**  
`chrome-devtools-mcp` 若不特别配置，会**单独启动**一颗 Chrome，用户数据在类似 `%USERPROFILE%\.cache\chrome-devtools-mcp\chrome-profile-stable` 的目录里——**没有你在默认浏览器里登过的账号**，观感会像无痕/新环境。  
要用**默认配置档、已有登录态**，推荐在 Cursor 的全局 MCP 里为 `chrome-devtools-mcp` 增加参数 **`--autoConnect`**（需 **Chrome 144+**）：先在已正常使用的 Chrome 中打开 `chrome://inspect/#remote-debugging` 按提示开启远程调试；再重启 Cursor / 重载 MCP。连接时 Chrome 会弹出授权，选允许后，MCP 会连到你**当前正在用的默认 Profile**（见 [Chrome DevTools MCP 说明](https://github.com/ChromeDevTools/chrome-devtools-mcp)）。  
备选：用 `--browser-url=http://127.0.0.1:9222` 连接你**手动用调试端口启动**的 Chrome（官方要求调试实例使用**非默认** user-data-dir 时，仍与日常主配置分离，需自行权衡）。

**协作约定（需要登录时）**

1. 让 AI 用 DevTools MCP 打开对应平台的写作/发布入口（见下表链接）。
2. 若出现登录页、验证码、二次验证：**由你在该 Chrome 窗口内自行完成**，AI 无法代收短信或代输密码。
3. 你登录完成后，回复 **「已登录」或「继续」**，AI 再继续：进入编辑器、粘贴正文（来自本文列出的 `docs/推荐文章/*.md`）、必要时协助检查标题与标签；**最终是否点击发布仍由你确认**，以免误发。

**前置条件**：按上节选好「独立 MCP 配置档」或「`--autoConnect` 连默认 Chrome」；需要登录时仍在**被连接的那颗浏览器**里操作。

## 各站快速操作备忘（下次复用）

**目的**：下次发文按下面顺序做即可，不必再整站分析。Chrome DevTools MCP 里元素的 **`uid` 会随页面刷新变化**，以当次 `take_snapshot` 为准；若某站未改版，通常仍是「标题框 + 正文框 + 发布按钮」三类控件。

### MCP 通用顺序（各站类似）

1. 你在已连接的 Chrome 里**登录**目标站（验证码、密码自理）→ 回复「已登录 / 继续」。
2. `list_pages` 选中写作页；若没有 → `navigate_page` 打开下文表格里的「写作入口」URL。
3. `take_snapshot`（必要时 `verbose: true`）→ 记下**标题**、**正文**对应控件的 `uid`。
4. 读入选用正文 `.md`（UTF-8），`fill` 标题；正文能 `fill` 则 `fill`。**CSDN Markdown 正文**：不要用 `fill` 灌正文，改用 **`copy_recommend_md_to_clipboard.ps1` + Ctrl+V**（见下节「为什么 fill 没有格式」）。在默认富文本里直接贴整段 `.md` 也会当成纯文本。
5. 点击「发布 / 发布文章 / 提交」→ 按弹窗选**原创/转载**、**分类**、**标签**等 → 二次确认。
6. 发布后 `list_pages` 看 URL 是否变为文章详情页，把**正式链接**记回表格「已发布链接」列。

| **思否** | 写作页填标题、正文（Markdown/富文本以页面为准）后提交。 |

### CSDN：为什么「自动化填了」却**没有格式**？

- **根因**：左侧 MD 区多为 **CodeMirror** 等组件；DevTools MCP 的 **`fill` 往往只写入无障碍层/外层 DOM**，**没有触发编辑器的 `input` / `change` 与内部文档模型**，保存时仍按「未正确解析的文本」或错误 HTML 提交，**线上就像一坨无排版纯文字**。
- **可靠做法（任选其一）**  
  1. **剪贴板真粘贴**：`.\scripts\copy_recommend_md_to_clipboard.ps1` 把 `DataAI推荐.md` 拷进剪贴板 → 打开 MD 编辑页 → 正文区单击 → **Ctrl+A** 清空 → **Ctrl+V**。这与你在 VS Code 里复制再粘贴一致，编辑器会正常解析 `#`、`**`、表格等。  
  2. **接口发布**：`python scripts/publish_csdn_post.py --file docs/推荐文章/DataAI推荐.md`（需 `CSDN_COOKIE`），直接 POST `markdowncontent`，不经过页面编辑器。  
  3. **富文本 + 带格式复制**：在创作页切 **「使用富文本编辑器」**，从 **Word** 或 **浏览器里已渲染好的页面** 复制（保留粗体、标题级别等），再 **Ctrl+V**；适合不想维护 Markdown 源码的场景，但与 `.md` 工作流是两条路。
  4. **创作中心富文本 iframe**：若用 DevTools **`fill`** 写入 iframe 内正文，页面可能仍显示「共 0 字」、提交时报「请输入文章内容」。需在正文区**补一次真实键盘变更**（如焦点后空格再退格）或脚本对 `contenteditable` 派发 `input`/`change` 并 `focus`，使字数与校验同步后再点「发布博客」。

### CSDN：Markdown 发布流程与耗时（实录）

**uid 以当次快照为准**；正文优先 **剪贴板粘贴**，不要用 `fill` 灌正文。

| 阶段 | 做什么 | 耗时感受 / 说明 |
|------|--------|-----------------|
| 1. 进对编辑器 | 打开 **MD 编辑页**：`https://editor.csdn.net/md`；**改已有文**时带 `?articleId=<数字>`。勿在默认富文本里贴整段 `.md` 当纯文本。 | 导航通常 **1～3 秒**。 |
| 2. 拿控件 uid | `take_snapshot` 定位标题框、**发布文章**（正文若用手动粘贴可跳过给正文 `fill`）。 | **`verbose: true` 很慢**（快照可达 100KB+）；可先非 verbose。 |
| 3. 写入正文 | **推荐**：`copy_recommend_md_to_clipboard.ps1` → 正文区 **Ctrl+A、Ctrl+V**。勿对 MD 正文 `fill`。 | 粘贴后看**右侧预览**：标题、列表、加粗应正确；再保存/发布。 |
| 4. 第一次点「发布文章」 | 工具栏或底部 **发布文章**。 | 有时只打开侧栏 **「创作助手」**；需 **再点一次** 才出发布弹窗。 |
| 5. 发布弹窗 | 标签、**原创**、**摘要**（自动摘要异常时手改）。 | 约 **0.5～2 分钟**。 |
| 6. 确认成功 | 成功页 `.../creation/success/<articleId>`；详情 `.../article/details/<articleId>`。 | 跳转 **1～5 秒** 常见。 |

**备选（少开浏览器）**：`publish_csdn_post.py`（见脚本说明）。

## 合规与账号说明

- 各站发帖应使用**你本人或团队官方账号**，并完成手机/邮箱/人机验证；**不应**由自动化工具代注册、代持号。
- Cursor **内置浏览器**与本地 Chrome **会话不共享**，且无法代你收短信验证码；仅靠内置浏览器时，未登录则无法代发文。
- 若使用 **Chrome DevTools MCP** 连接本机 Chrome，可复用你在该浏览器中的登录态；**需要登录时等你操作**，流程见上文「用 Chrome DevTools MCP 协作发文」。
- 若需 AI 辅助填表，也可在**你已登录的浏览器**中自行粘贴正文；或使用上文脚本 + 环境变量在支持 API 的平台发布。
